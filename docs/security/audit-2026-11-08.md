### SEC-001 — A quotation's prices can be used on another customer's invoice

- **Where:** `convertibleQuotation()` (`src/server/services/invoicing.ts:70`) checks only that the
  quotation is not converted or cancelled; `createInvoice` (`:126`) and `previewInvoice` (`:335`)
  then apply its quoted prices to whatever `customerId` the form sends.
- **How it could be attacked:** a staff member makes a quotation for a Wholesale customer (priced
  from the Wholesale tier), then creates a cash invoice for the walk-in customer (or a friend on
  Retail) with that `quotationId` (a direct POST, or by changing the customer in the editor). The
  invoice gets Wholesale prices. **Proved on the local test database:** a part priced Retail 1000.00
  / Wholesale 850.00 was invoiced to the walk-in customer at **850.00**. This gets around both the
  price tiers and the staff discount cap, and marks the Wholesale customer's quotation as converted
  to someone else's invoice.
- **Why it happens:** the quotation is not tied to the invoice's customer.
- **Fix:** in `convertibleQuotation` (or right after it in both callers), refuse when
  `quote.customerId !== data.customerId` (`InvalidState("<number> is for another customer")`);
  return `customerId` from `loadQuotationPrices`. Check the editor fixes the customer when it starts
  from a quotation.
- **How we prove it's fixed:** a Vitest case in `tests/services/quotation-conversion.test.ts`:
  converting a Wholesale quotation on a walk-in invoice throws, and the quotation stays open.
- **References:** OWASP Top 10 A01 (Broken Access Control) / business-logic abuse; ASVS V11 (business logic).

### SEC-002 — Next.js 15.5.28 → 15.5.29

- **Where:** `package.json` `next@15.5.28`.
- **How it could be attacked:** not exploitable here today — the three 15.x advisories need Edge route
  handlers that set cookies, remote image sources, or a route handler forwarding a fetched response.
  A future change could add one of those.
- **Fix:** upgrade to 15.5.29. The scroll patch (`patches/next@15.5.28.patch`) must be re-made for
  15.5.29 (the bug is still there in 15.5.29). Run the full prod-build e2e, click-test the preview.
- **How we prove it's fixed:** `pnpm list next` shows 15.5.29; e2e scroll tests pass.

### SEC-003 — No Content-Security-Policy

- **Where:** `next.config.ts:14` sets X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy and
  HSTS, but no CSP.
- **How it could be attacked:** only as a second layer: if an XSS bug were ever added, a CSP would
  stop injected scripts from running or sending data out. No XSS sink was found today (React escaping,
  no user HTML, logo restricted to PNG/JPEG with nosniff).
- **Fix:** start with `Content-Security-Policy-Report-Only` (`default-src 'self'`, `img-src 'self'
  data:`, `style-src 'self' 'unsafe-inline'`, `script-src 'self' 'unsafe-inline'` or nonces,
  `frame-ancestors 'none'`), watch for breakage, then enforce.
- **How we prove it's fixed:** response headers on the preview; e2e still green.

### SEC-004 — Deploy workflow supply chain

- **Where:** `.github/workflows/deploy.yml` — `npm install --global vercel@latest` (:43), actions by
  tag (`@v4`), no `permissions:` block.
- **How it could be attacked:** if a future `vercel` CLI release (or an action tag) were hijacked, as
  in this year's npm worms, it would run with the Vercel deploy token in the environment.
- **Fix:** pin `vercel@<exact version>`; add `permissions: contents: read`; optionally pin actions
  by commit SHA.
- **How we prove it's fixed:** workflow diff; next deploy succeeds.

### SEC-005 — Someone can lock a known user out of login for up to an hour

- **Where:** `src/server/services/sign-in.ts:8` — 10 failed tries per email per hour.
- **How it could be attacked:** anyone who knows a staff member's email types 10 wrong passwords;
  that person can't log in for the rest of the hour (the per-device limit doesn't help because the
  key is the email).
- **Fix (choose):** accept (small shop, internal emails), or raise the per-email limit and rely more
  on the per-device limit, or let a correct password through once the device limit is still fine.
- **How we prove it's fixed:** a sign-in test for the chosen rule.

### SEC-006 — `apply_held_credit` has no fixed search_path and is callable through the Data API

- **Where:** `drizzle/0008_apply_held_credit.sql:7` (Supabase advisor: function_search_path_mutable).
- **How it could be attacked:** functions in `public` can be called by the `anon` role through
  Supabase's `/rest/v1/rpc`. It runs as the caller (SECURITY INVOKER), and every table is RLS
  deny-all, so today a call does nothing. It becomes risky only if someone later makes it SECURITY
  DEFINER or adds policies.
- **Fix:** a migration: `alter function public.apply_held_credit(uuid) set search_path = public,
  pg_temp; revoke execute on function public.apply_held_credit(uuid) from public, anon,
  authenticated;` — applied to cloud through the normal migration process (Owner approves; not run
  by the audit).
- **How we prove it's fixed:** the Supabase security advisor no longer lists it; invoicing tests pass.

### SEC-007 — Old logo-link download accepts any host

- **Where:** `src/server/services/logo.ts:59` — `OLD_STORAGE_LINK` matches `https://<any host>/storage/v1/object/public/…`.
- **How it could be attacked:** an admin (only admins can change Settings) could point the logo at
  another server's `/storage/v1/object/public/` path and make the app fetch it when printing a PDF
  (server-side request). Limited: https only, that path only, 3 s, and the reply is used only if it
  is a PNG/JPEG.
- **Fix:** remove the old-link branch once the owner re-uploads the logo (already planned), or pin the
  host to the project's Supabase host.
- **How we prove it's fixed:** `tests/services/logo.test.ts` case for a foreign host → null.

## 5. Passed checks

- **Server Actions:** all 37 non-public actions call `requireUser()` (scripted check of every export in
  `"use server"` files). Admin-only work is enforced in services with `requireRole`: parts/categories/
  brands/models, price tiers and bulk price change, users (incl. last-admin guard), settings, logo,
  invoice cancel, sales targets, reconciliation, sales analytics, stock health.
- **Public actions:** setup (24+ char key, constant-time compare, per-device limit, advisory lock +
  "company exists" re-check, runs once), login (per-email + per-device limits, one generic error,
  turned-off accounts refused and their sessions ended), logout, forgot/reset password (same answer
  for every email and done after the reply, 6-digit CSPRNG code stored as HMAC, 15 min, 5 tries,
  per-device and per-email limits).
- **Better Auth:** no `/api/auth` route mounted; sign-up disabled; secret ≥ 32 chars enforced; every
  request re-reads the session (no cookie-cache trust); bcrypt cost 10.
- **Middleware** is not relied on for security (pages and routes check the session themselves).
- **Route handlers:** all check sign-in except `/api/health` and `/api/logo` (logo is public-safe:
  PNG/JPEG only by magic bytes, nosniff). Daily report is admin-only.
- **Money rules:** invoice prices come from the server (tier / valid quotation), staff discount cap
  enforced on create and preview, credit-limit override and backdating admin-only, explicit payment
  allocations admin-only, returns limited to returnable qty, staff stock adjustments limited to
  decreases for damage/lost.
- **Cost/profit data:** `toStaffView` strips `avgCost`/`unitCost` for staff (invoice lines, part
  detail); parts search returns no cost; sales & profit and stock health admin-only.
- **Injection:** no user input in `sql.raw` (only code constants); `dangerouslySetInnerHTML` only in
  the chart's colour style from code; CSV cells starting with `= + - @` are escaped.
- **Secrets:** only `.env.example` tracked; no keys/connection strings in tracked files; no
  `NEXT_PUBLIC_` variables.
- **Database:** RLS enabled with no policies on all 36 public tables (deny-all to the Data API); the
  app connects as the owner role.
- **Rate-limit IP:** `CLIENT_IP_HEADER` only trusted where the Docker stack has no open port; on
  Vercel the platform's `x-forwarded-for` is used.
